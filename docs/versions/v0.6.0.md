# v0.6.0 — Rel kanan, drawer menempel, dan pembersihan modul native

> **Catatan:** tata letak rel kanan (bagian 1) **dibatalkan di v0.7.0** karena membuat editor sempit dan tidak nyaman. Pembersihan modul native (bagian 2) tetap berlaku. Gambar rancangan rel kanan sudah dihapus dari `docs/preview/`.

Tanggal: 7 November 2026 · versionCode 9

Dasar: 3 screenshot dari v0.5.1 dan rancangan tata letak dari pengguna.

## 1. Tata letak baru (sesuai rancangan)
```
+------------------------------------------+------+
| [Beranda] [index.html] ...   <- tab atas |  ☰   |
|                                          |  ⋮   |
|              area editor                 | n    |
|                                          | a    |   nama file + path
|                                          | m    |   MIRING vertikal
|                                          | a    |
|                                          |  ✎   |   ikon tetap tegak
|                                          |  ▶   |
+------------------------------------------+------+
| SHFT  TAB  cari  undo  redo  ...  (dok tombol keyboard, tidak berubah)
+-------------------------------------------------
| ■  ●  ◀   (tombol navigasi Android, tidak berubah)
```
- **Tab berkas** kembali ke **atas layar** (Beranda, index.html, dan seterusnya).
- **Top bar jadi rel vertikal di sisi kanan**, dari atas ke bawah: ☰ (buka sidebar), ⋮ (menu), nama file + path yang **dimiringkan** (tulisan vertikal), ✎ (pensil), ▶ (pratinjau). Ikon tetap tegak, hanya tulisan yang miring.
- Rel **berhenti di atas dok tombol keyboard**; dok itu dan tombol navigasi Android tidak diubah dan tidak tertimpa.
- **Drawer menempel di sisi kiri rel** dan dibuka/ditutup dengan ☰ di rel. **Ikon tab drawer (Berkas, Cari) ada di atas**, sejajar dengan ☰ dan rata kanan (tepat di sebelah kirinya); di bawahnya isi (pohon folder) mulai dari atas seperti aslinya. Drawer tidak menutupi rel.
- **Menu ⋮ dan menu ✎** terbuka di sebelah kiri rel (✎ terbuka ke atas dari bawah rel), tidak menimpa rel.
- **Geser** membuka drawer: mulai dari tepi kiri rel, geser ke kiri; geser ke kanan untuk menutup. Gulir vertikal di editor tidak terganggu (arah gerakan dideteksi dulu).
- Mode layar penuh (fullscreen) tetap memakai tata letak bawaan.

Berkas utama: `src/styles/webcode-ui.scss`, `src/components/sidebar/index.js`, `src/main.js`, `src/lib/settings.js`.

**Migrasi pengaturan:** karena v0.5.1 memindahkan tab ke bawah, v0.6.0 mengembalikannya ke atas **sekali saja** (`wcLayoutV2`). Pilihan yang kamu ubah sesudahnya tidak ditimpa lagi.

## 2. Modul native yang dibuang (sisa-sisa)
Folder berikut **dihapus** dari `src/plugins/` dan dari `package.json` (karena `utils/setup.js` memasang SEMUA folder di `src/plugins`, menghapus entri saja tidak cukup):

| Dibuang | Isinya |
|---|---|
| `terminal` | layanan terminal, `Executor`, penyedia dokumen "Alpine" yang tampil di aplikasi Berkas sistem |
| `auth` | penyimpanan terenkripsi akun/login |
| `pluginContext` | konteks plugin Acode |
| `ftp`, `sftp` | koneksi FTP dan SFTP (online) |
| `iap`, `proot` | pembelian Google Play dan runtime Alpine (tidak terpakai sejak v0.1.0) |

Perubahan pendukung:
- `RewardPassManager.java` (sisa iklan berhadiah) memakai plugin `auth`, jadi **dihapus** beserta field, inisialisasi, dua aksi (`getRewardStatus`, `redeemReward`) di `System.java`, entri di `plugin.xml`, dan dua fungsi di `www/plugin.js`.
- `main.js`: migrasi profil SFTP saat start dan dialog laporannya dibuang.
- Menu "tambah FTP/SFTP" di pengelola berkas dibuang.
- `package-lock.json` dirapikan agar sinkron.
- Folder `admob` **dipertahankan** (tidak dipasang pada varian `paid`, tetapi test bawaan Acode bergantung padanya).

Yang masih ada sebagai kode JS mati (tidak terpanggil, tidak menyentuh plugin saat dimuat): halaman plugin/sponsor/iklan dan modul FTP/SFTP/terminal. Diperiksa tidak ada akses ke plugin saat modul dimuat, jadi tidak menyebabkan crash startup. Membuangnya total dari bundel bisa dikerjakan terpisah.

Server bahasa bawaan (TypeScript/JavaScript, CSS, HTML, JSON yang berjalan di dalam app) tidak terpengaruh. Server eksternal (mis. Python) memang butuh terminal dan nonaktif secara bawaan.

## 3. Diverifikasi
- Build produksi sukses; **927 test lulus**.
- Aplikasi asli dijalankan di Chromium (Android ditiru): tab di atas, rel kanan dengan urutan ikon dan teks miring, drawer menempel dengan ikon tab di atas, menu ⋮ di sebelah kiri rel, tema WebCode Night dan Hacker. Gambar: `docs/preview/rel-kanan-*.png`.

- Tampilan dan gestur di HP sungguhan; ukuran rel (54 px) dan lebar drawer mungkin perlu disetel.
- Menu ✎ saya posisikan dari bawah rel; uji penuh di aplikasi tiruan terganggu error bawaan alat uji (encoding berkas baru), bukan dari perubahan ini.

## 5. WAJIB saat memasang
Karena plugin native berkurang, bersihkan platform lama dulu:

```
cd platforms\android; .\gradlew.bat --stop; cd ..\..
Remove-Item -Recurse -Force platforms, plugins
Remove-Item -Recurse -Force src\plugins\terminal, src\plugins\auth, src\plugins\pluginContext, src\plugins\ftp, src\plugins\sftp, src\plugins\iap, src\plugins\proot
Remove-Item src\plugins\system\android\com\foxdebug\system\RewardPassManager.java
npm install --legacy-peer-deps
npm run setup
npm run build -- paid d fdroid apk
```
(Git Bash: `rm -rf platforms plugins src/plugins/{terminal,auth,pluginContext,ftp,sftp,iap,proot} src/plugins/system/android/com/foxdebug/system/RewardPassManager.java`.)
Baris `Remove-Item ... src\plugins\...` perlu karena paket pembaruan hanya menimpa/menambah file, tidak menghapus. Kalau folder lama tertinggal, `npm run setup` akan memasangnya lagi.
