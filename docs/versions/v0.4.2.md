# v0.4.2 — Perbaikan urutan hook (error `setFullscreenBackHandler`)

Tanggal: 4 November 2026 · versionCode 6

## Gejala
Setelah hook `prettier` lolos (v0.4.1), `rspack` sukses dan Gradle mulai mengompilasi, build gagal dengan 2 error di `System.java`:

```
System.java:188: error: cannot find symbol
  ((CordovaWebViewImpl) webView).setFullscreenBackHandler(fullscreenBackHandler);
  symbol: method setFullscreenBackHandler(boolean)  location: class CordovaWebViewImpl
System.java:199: error: cannot find symbol
  ((CordovaWebViewImpl) webView).setFullscreenOrientation(orientation);
```

## Penyebab
Kedua method itu ditambahkan ke `CordovaWebViewImpl.java` oleh hook `hooks/immersive-fullscreen.js` (`after_prepare`). Tetapi hook `hooks/modify-java-files.js` (`before_prepare`) memanggil `main();` **tanpa ditunggu**: Cordova menganggapnya selesai seketika, lanjut ke `prepare` dan `after_prepare`, sementara `modify-java-files.js` masih memformat file dengan prettier lalu menulisnya belakangan dari salinan yang sudah dibaca di awal. Hasilnya patch `immersive-fullscreen.js` tertimpa. Di log kamu terlihat jelas: baris `...CordovaWebViewImpl.java updated` muncul **setelah** "Checking Java JDK and Android SDK versions".

Di mesin cepat, hook sering menang balapan, jadi Acode asli tampak normal. Di mesin yang sedang berat (log kamu menunjukkan 15 Gradle daemon sibuk dan rspack 940 detik) hook kalah.

Ini bug bawaan Acode, bukan akibat perubahan kita.

## Perbaikan (`hooks/modify-java-files.js`)
- Modul sekarang mengekspor fungsi yang **mengembalikan promise**, sehingga Cordova menunggu sampai semua file selesai ditulis sebelum lanjut.
- Penulisan file dibuat sinkron (`writeFileSync`); error sekarang menggagalkan hook (bukan `process.exit` di dalam callback).
- File penanda `.flag_done` ditulis paling akhir, hanya jika semua file berhasil ditulis.

## Diverifikasi
- Simulasi dengan source Cordova sungguhan (`cordova-android` 15 dari `node_modules`):
  - Urutan hook **asli**: patch fullscreen hilang (`setFullscreenBackHandler` tidak ada), mereproduksi error persis seperti di log kamu.
  - Urutan hook **baru**: `setFullscreenBackHandler`, `setFullscreenOrientation`, `setInputType` (patch lain), dan `ImmersiveFullscreen.java` semuanya ada; build kedua identik dan tanpa marker ganda.
- Test regresi `tests/unit/modifyJavaFilesHook.test.js` memuat skenario ini (dilewati otomatis di Windows).
- Dari log kamu: kode Java kita (`Browser.java`, `WebDownloads.java`) tidak muncul di daftar error, artinya lolos kompilasi di Gradle sungguhan.

## Belum diverifikasi
Build APK lengkap sampai file `.apk` jadi, serta jalannya aplikasi di HP.

## Cara memakai
1. Timpa file dari paket hotfix.
2. Karena folder `platforms` kamu dibuat saat bug terjadi, bersihkan dulu supaya patch diterapkan berurutan dari awal (PowerShell):

```
cd platforms\android; .\gradlew.bat --stop; cd ..\..
Remove-Item -Recurse -Force platforms, plugins
npm run setup
npm run build -- paid d fdroid apk
```

(Di Git Bash: `rm -rf platforms plugins`.) Rspack hasil sebelumnya (`www/build`) tidak perlu dihapus.

Jalan pintas: karena `.flag_done` sudah terisi, **menjalankan ulang build saja kemungkinan juga lolos**, sebab `immersive-fullscreen.js` akan menambal ulang file yang sudah diubah. Tetapi pembersihan di atas lebih pasti.
