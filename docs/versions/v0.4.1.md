# v0.4.1 — Perbaikan build di Windows

Tanggal: 3 November 2026 · versionCode 5

## Gejala
Saat `npm run build -- paid d fdroid apk` di Windows (Git Bash), build berhenti di tahap `cordova build android` dengan:

```
Error: ENOENT: no such file or directory, open
'G:\G:\Projects\Irham.s.a-WebCodeIDE\node_modules\prettier-plugin-java\dist\tree-sitter-java_orchard.wasm'
```

Tahap `rspack` sendiri sudah sukses; yang gagal adalah hook Cordova `hooks/modify-java-files.js`.

## Penyebab
Hook itu merapikan file Java dengan `prettier-plugin-java`. Plugin membuat path file wasm-nya dari `new URL(...).pathname`, yang menghasilkan `/G:/Projects/.../x.wasm`. Di Windows, Node membaca path berawalan `/` sebagai "root drive saat ini", sehingga menjadi `G:\G:\Projects\...`. Versi CJS dan ESM dari plugin (2.9.1) sama-sama punya bug ini, jadi bukan kesalahan setup dan bukan soal lokasi proyek. Kode ini bawaan Acode, bukan perubahan kita.

## Perbaikan
- File baru `hooks/lib/win-path-fix.js`: membungkus `fs.promises.readFile` (juga `readFileSync` dan `readFile`) dan membuang `/` di depan huruf drive. Aktif **hanya di Windows**; di sistem lain tidak melakukan apa-apa.
- `hooks/modify-java-files.js` memanggil `install()` sebelum `prettier` dimuat. Kalau pemformatan tetap gagal, hook sekarang mencetak pesan jelas dan **berhenti** (tidak dilewati), karena patch Java bergantung pada hasil format; melewatinya bisa menghasilkan APK yang rusak tanpa tanda.
- Test: `tests/unit/winPathFix.test.js` (path diperbaiki, path lain tidak disentuh, tidak aktif di Linux, dan panggilan `await import("fs/promises")` seperti yang dilakukan `web-tree-sitter` ikut terbungkus).

## Diverifikasi
- 4 test baru lulus; formatter `prettier-plugin-java` tetap bekerja di Linux dengan perubahan ini; sintaks hook valid.
- **Belum** bisa diuji di Windows asli (lingkungan pembuatan paket ini Linux). Mekanisme pembungkus diuji dengan fungsi tiruan, bukan dengan file wasm sungguhan di Windows.

## Cara memakai
Timpa file yang berubah (lihat paket hotfix), lalu jalankan lagi:

```
npm run build -- paid d fdroid apk
```

Kalau build sebelumnya berhenti di tengah, tidak perlu membersihkan apa pun: hook gagal sebelum mengubah file Java, jadi aman diulang.
